# 苏作创意台

## 产品介绍与方案总览

> 文档版本：v1.0
>
> 产品定位：面向文创设计团队的语音优先、文化可追溯、二维到贴图三维验证的一体化设计工作台。
>
> 当前形态：本机单用户 Demo，正在按《苏作创意台 2.0 详细产品设计文档》实现。

## 1. 一句话介绍

苏作创意台把文创设计师的想法、文化依据、二维概念、贴图三维、评审意见和提案交付放进同一个项目上下文中，让设计从“灵感生成”变成一条可解释、可追溯、可继续推进的工作流。

它不是单纯的 AI 生图工具，也不是传统项目管理软件，而是连接“文化研究”和“视觉生成”之间的设计记忆系统。

## 2. 为什么要做

文创设计的真实工作通常分散在多个工具里：

```text
会议/语音灵感 → 聊天记录 → 生图工具 → 文件夹版本 → 3D 工具 → 即时通讯评审 → PPT 提案
```

这种方式有几个长期问题：

- 灵感、修改意见和最终作品之间缺少关联；
- 二维图好看，但不能快速验证体块、比例、空间和材质；
- 设计师说“轻一点”“更年轻”“保留漏景”，AI 很难同时理解变化和必须保留的内容；
- 文化元素经常被简化成装饰符号，无法说明事实、转译和 AI 推断的边界；
- V1、V2、V3 分散在文件夹里，旧版本为什么被淘汰、三维依据哪张图生成，都很难追查；
- 客户提案需要重复整理图片、文化出处、设计说明和版本变化。

苏作创意台解决的不是“再生成一张图”，而是把这些分散的设计决策连接起来。

## 3. 产品解决的核心问题

### 3.1 把自然表达变成设计事实

设计师可以直接说：

> 我想做一个适合年轻人桌面使用的苏州园林香插，不要仿古，希望有漏景和留白的感觉。

系统会把这句话整理为：

- 产品类型：桌面香插；
- 目标用户：年轻用户；
- 使用场景：桌面；
- 文化线索：漏景、留白；
- 风格方向：现代、克制、非仿古；
- 待确认内容：材质、尺寸、结构和生产可行性。

用户不需要先填写一张复杂表单，但关键设计事实必须在界面上可见并可修正。

### 3.2 把文化知识变成设计转译

系统不把“苏州文化”当成一个风格按钮，而是拆成可解释的层次：

```text
文化事实 → 设计转译 → 形态/空间/材质/功能规则 → 视觉方案
```

例如：

```text
事实：漏景通过遮挡、开口和前后关系形成观看层次
转译：前后体块、局部开口、烟气穿行路径
产品应用：香插的框景、镂空和烟气体验
```

所有文化资料都显示类型和核验状态：

| 类型 | 含义 | 是否可以直接作为历史事实 |
| --- | --- | --- |
| 文化事实 | 有来源的文化信息 | 只有已核验后可以 |
| 设计转译 | 设计师对文化逻辑的当代转化 | 不是历史事实 |
| 设计师判断 | 用户或负责人做出的设计决策 | 不是历史事实 |
| AI 推断/生成内容 | 模型根据上下文提出的假设 | 不能直接对外使用 |
| 待核验 | 尚未补足证据的内容 | 不能进入客户提案 |

### 3.3 让二维到三维不是两次独立生成

三维不是从另一段文字重新猜一个模型，而是从用户明确锁定的二维候选图进入 Rodin Image to 3D：

```text
二维候选 A-V3
    ↓ 唯一主参考图
Rodin Image to 3D
    ↓
带 PBR 材质贴图的 GLB
    ↓
三维预览、材质检查、来源追溯和评审
```

三维资产必须记录：

- 来源二维资产；
- 设计方向和版本；
- 输入模式；
- 生成任务和时间；
- PBR 材质检查结果；
- 当前状态是最终、预览、失败还是旧版本。

如果二维候选切换，旧三维自动标记为 `stale`，不能继续显示为当前最终模型。

## 4. 核心用户与价值

| 用户 | 主要工作 | 苏作创意台提供的价值 |
| --- | --- | --- |
| 文创设计师 | 说想法、做方向、改方案 | 不填复杂表单，直接用自然语言推进设计 |
| 设计负责人 | 比较方向、评审和定稿 | 看清版本变化、保留项和风险 |
| 文化顾问/工艺师 | 核验来源和工艺表达 | 区分事实、转译、推断和待核验 |
| 客户/品牌方 | 看确认后的方案 | 只看到可交付的作品和设计叙事 |
| 项目协作者 | 补充场景、材质、结构和交付资料 | 在项目上下文中补资产，不丢来源 |

## 5. 完整工作流

### 5.1 主流程

```text
项目
  → 设计方向
  → 语音/文字表达
  → AI 复述和 Brief
  → 文化依据与设计转译
  → 二维概念生成
  → 修改补丁
  → 锁定二维候选
  → Rodin 贴图三维
  → 内部评审
  → 提案选材
  → HTML/PDF 打印交付
  → 项目和资产沉淀
```

### 5.2 每一阶段的输入和产物

| 阶段 | 用户在做什么 | 系统沉淀什么 | 推进门槛 |
| --- | --- | --- | --- |
| 灵感捕捉 | 说出目标和限制 | 录音状态、转写、AI 复述、Brief | 核心理解被确认 |
| 文化依据 | 选择文化资料和转译方向 | 来源卡、文化类型、核验状态 | 事实和创作边界清楚 |
| 概念探索 | 生成和比较二维方向 | 图片、Prompt 摘要、版本关系 | 方向可讨论 |
| 三维验证 | 锁定二维并生成模型 | PBR GLB、来源二维、任务记录 | 当前候选和有效图像存在 |
| 评审迭代 | 记录通过或修改意见 | 评审记录、设计补丁、下一版基线 | 版本决策明确 |
| 提案交付 | 选择资产和生成提案 | HTML、manifest、文化说明、下载清单 | 客户门禁通过 |
| 复用沉淀 | 查找过去做过的内容 | 文化、材质、结构、Prompt、版本和语音资产 | 可被未来项目检索 |

## 6. 产品界面

### 6.1 项目首页

项目首页回答三个问题：

1. 我有哪些项目；
2. 每个项目现在进行到哪一步；
3. 我下一步应该继续什么。

项目卡显示：项目名、当前方向、最新版本、阶段、二维/三维数量、待处理事项、最近更新时间和“继续工作”按钮。

### 6.2 三栏工作台

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目名   灵感 → 依据 → 二维 → 三维 → 评审 → 提案   当前状态 │
├─────────────────┬──────────────────────────┬─────────────────┤
│ 设计对话         │ 当前作品画布             │ 设计状态         │
│                 │                          │                 │
│ AI 复述          │ 二维 / 三维 / 对比 / 关系 │ 当前方向         │
│ 用户表达         │                          │ Brief            │
│ 修改意见         │ 版本信息                 │ 文化依据         │
│                 │                          │ 下一步           │
│ 按住说话         │ 继续修改 / 锁定 / 生成3D  │ 阶段门           │
└─────────────────┴──────────────────────────┴─────────────────┘
```

- 左栏负责表达和确认，不只是聊天记录；
- 中央负责看作品、对比版本和查看模型；
- 右栏负责解释当前事实、文化来源和下一步条件。

### 6.3 作品库和资产库

作品库有两种视图：

- **方案视图**：按项目、方向、版本查看设计演变；
- **资产视图**：按二维、三维、文化、材质、结构、对话、提案查看可复用资源。

每个资产支持搜索、组合筛选、详情、来源关系、下载、归档、设为候选和加入提案。

资产卡必须显示：

- 类型和状态；
- 所属方向和版本；
- 父版本；
- 关联三维；
- 文化来源及其类型/核验状态；
- 是否当前候选；
- 是否已经进入提案。

### 6.4 评审中心

评审中心按“待处理 → 已通过 → 需要修改 → 保留备选 → 淘汰”组织工作。

每条意见必须绑定项目、方向、版本、资产和区域，例如：

```text
对象：A-V3-3D
区域：底座
意见：视觉上仍然偏轻，需要增强稳定感
操作：生成下一版修改补丁
```

### 6.5 提案页

提案只消费明确选中的资产，不把作品库中所有结果自动塞进去。默认包含：

1. 项目封面；
2. 设计背景；
3. 文化依据；
4. 设计转译；
5. 二维概念；
6. 三维贴图模型截图；
7. 材质和功能说明；
8. 版本变化；
9. 限制和待验证项；
10. 后续打样建议。

P0 使用 HTML 提案和浏览器打印 PDF；同时提供 `asset-manifest.json`，记录提案使用的全部资产。

## 8. 苏州文化壁垒

产品的壁垒不在于“调用了某一个模型”，而在于将地方文化转化成可复用的设计知识体系：

### 8.1 文化证据链

每个文化元素都记录来源、摘要、核验状态和使用版本，客户可以知道“为什么这样设计”。

### 8.2 文化转译库

把苏州园林、丝绸、昆曲、水乡、工艺等内容拆成空间、比例、纹样、色彩、材质、光影、声音和使用场景规则，而不是只保存关键词。

### 8.3 设计结果反哺知识

优秀项目完成后，设计师可以把“文化事实 → 转译规则 → 产品形态 → 评审结论”沉淀为下一项目可复用的方向模板。

### 8.4 可信度门禁

内部方案可以保留待核验内容，但客户提案必须阻断未核验文化事实。这个规则让产品在文化表达上区别于普通生图工具。

## 10. 技术实现概览

### 10.1 前端

- React + TypeScript + Vite；
- 三栏工作台和顶层页面状态；
- Three.js/React Three Fiber 预览 GLB；
- 不引入复杂路由或新的状态管理框架；
- Chrome 桌面端优先，基准 1440×900，最低完整视口 1280×720。

### 10.2 后端

- FastAPI；
- P0 单用户内存工作区；
- 项目、方向、版本、资产、评审、提案统一通过 projectId 隔离；
- 图片走 OpenAI-compatible provider；
- 三维走 Hyper3D/Rodin Image to 3D；
- 本地文件保存在项目输出目录。

### 10.3 关键技术契约

- 每次生成创建不可变版本；
- 同项目同类任务处理中时阻止重复提交；
- Rodin 只接受锁定的二维候选；
- 最终三维必须是可解析、带 PBR 材质贴图的 GLB；
- 旧候选的三维自动变为 `stale`；
- 提案选材保存为项目级 `proposal_asset_ids`；
- 客户提案拒绝未核验文化事实和不合格资产。

- 三栏工作台、画布模式、生成确认卡；
- 作品库、资产详情和资产关系视图；
- 项目级提案选材、候选切换刷新、文化标签和归档 modal。

本轮已继续实现并在真实本地前后端和 Chrome 中验证：

```text
项目首页 → 进入项目 → 对话输入 → 确认修改并生成二维 → 锁定候选
→ 进入三维 → Rodin 失败状态/重试入口 → 作品库 → 版本评审 → 内部/客户提案门禁
```

验证观察：

- 普通对话只记录表达和设计理解，不会自动创建生成任务；明确确认后才推进二维生成。
- 二维生成完成后必须锁定候选，三维入口才可用；Rodin 失败不会伪造白模或最终模型，而是显示阻塞原因和重试入口。
- 作品库显示当前项目的二维资产、候选状态、文化类型和核验状态；评审意见绑定版本、资产和区域。
- 客户提案会阻止未核验文化事实，显示 `verified_culture` 缺失原因和返回核验入口；内部提案明确标注不可对外。
- 在 1280×720、1200×700 和 375×812 视口下，页面没有横向溢出；低于完整桌面尺寸时提示扩大窗口并按优先级收起侧栏。

自动化与端到端证据见 [苏作创意台端到端旅程清单](verification/suzuo-workbench-journey.json)。前端 64 个测试、后端 115 个测试均通过，生产构建通过；lint 只保留既有 React 规范警告。

仍未宣称完成的部分：真实 Rodin 云端成功返回、生产级多人协作、服务端 PDF 排版、精确结构/CAD 和量产工艺验证。这些属于外部依赖或后续范围。

## 13. 产品价值总结

苏作创意台的价值可以概括为：

```text
让设计师更快表达
让文化依据更可信
让二维和三维真正连起来
让每次修改都可解释
让每个结果都能沉淀和复用
让提案从整理文件变成自动生成
```

最终目标不是替代设计师，而是把设计师脑中的判断、文化理解和版本经验保存下来，并在下一次创作中继续发挥作用。

## 14. 面向用户的产品介绍

苏作创意台是一套为苏州文创团队设计的 AI 创意工作台。设计师可以直接用语音或文字描述一个想法，系统会把想法整理成设计 Brief，结合文化资料生成二维概念方案；确认某个二维候选后，再以它为唯一主参考生成带材质的三维模型。整个过程中的文化来源、修改理由、版本关系、评审结论和提案选材都会自动保留。

对设计师来说，它减少了在聊天工具、生图工具、三维工具、文件夹和提案软件之间来回切换；对负责人来说，它让“为什么选这一版”有证据；对文化顾问来说，它明确区分史实、设计转译和 AI 假设；对客户来说，它只展示经过筛选、可解释、可交付的方案。

## 15. 典型使用场景

### 场景 A：从一句话到二维方案

用户说“做一个年轻人桌面用的漏景香插，现代一点，保留框景和留白”。系统先复述目标、文化线索、风格和待确认内容，用户说“确认并生成”后才创建二维任务。生成完成后，用户可以继续讨论、整图修改或锁定候选。

### 场景 B：从二维候选到带材质三维

用户锁定 A-V3 后进入三维阶段，系统自动把 A-V3 作为 Rodin Image to 3D 的主输入，并显示来源关系。只有带有效 PBR 材质的 GLB 才能进入最终状态；失败任务保留错误原因和重试入口，不生成虚假的白模结果。

### 场景 C：文化资料核验后进入客户提案

客户提案尝试使用某个文化事实时，系统检查来源标题、来源地址或文件标识、摘要和核验时间。缺失时阻断提案并指出缺口；补齐并标记已核验后，文化内容才可进入客户安全版本。

## 16. 交互状态与反馈原则

每个会改变项目状态的操作都必须给出“当前状态、下一步和失败恢复”三类反馈：

| 操作 | 成功反馈 | 阻塞反馈 | 可恢复动作 |
| --- | --- | --- | --- |
| 确认生成二维 | 显示任务进度和目标版本 | Brief 或方向未确认 | 返回对话补充或确认 |
| 锁定候选 | 显示候选版本和进入三维入口 | 没有有效二维资产 | 返回作品库选择 |
| 生成三维 | 显示 Rodin 任务与贴图检查 | 服务失败、输入缺失或材质无效 | 重试、查看来源、回到二维 |
| 加入提案 | 显示项目级选材清单 | 资产失败、过期或不属于当前项目 | 查看详情、替换候选 |
| 客户提案 | 显示可对外资产 | 文化事实未核验或缺少模型 | 去核验、补资产、改用内部提案 |

界面文案优先使用设计语言，例如“二维候选未锁定”“文化来源待核验”“三维生成失败，请重试”，不把 provider ID、内部 job ID 或接口错误堆到主界面。

## 17. 产品验收清单

- 用户能从项目首页通过一句自然语言创建项目，不填写长表单。
- 用户能在同一项目中创建、激活和切换多个设计方向。
- 普通聊天不会误触发生成；确认后才创建二维任务。
- 二维结果能被锁定为唯一候选，并成为 Rodin 的可追溯输入。
- 三维结果必须有可解析 GLB 和 PBR 材质信息；失败不能伪装成最终作品。
- 作品详情至少包含预览、设计说明、来源关系、交付状态四个标签。
- 文化事实能在工作台内补充证据、保存和标记核验。
- 作品库能按项目、方向、类型、状态、文化和材质组合筛选。
- 评审意见绑定版本、资产和区域，并能形成下一版修改依据。
- 客户提案自动阻断未核验文化事实和失效资产。
- 提案选材属于项目级持久状态，刷新后仍保持一致。
- 1280×720 以上桌面视口无横向溢出，窄屏有明确降级策略。
