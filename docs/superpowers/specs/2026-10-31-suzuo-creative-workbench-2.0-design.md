# 苏作创意台 2.0 详细产品设计文档

> 文档状态：Draft v2.1（改进版），作为下一阶段产品设计与开发依据
>
> 基线文档：`2026-10-30-suzhou-cultural-workbench-prd.md`、`2026-10-31-image-to-3d-consistency-design.md`
>
> 本文是产品设计文档，不代表本轮已经开始实现。v2.1 在原 2.0 方案上补充了作品管理、资产沉淀、可解释交互、提案选材和阶段推进规则，并把 P0/P1 边界写成可验收的产品契约。

## 1. 设计结论

当前“语音对话 → 二维概念 → 锁定 → Rodin 三维 → 提案”的主链路适合 Demo，但还不足以支撑专业文创团队长期使用。2.0 将产品从“生成器”升级为“文创项目与设计资产工作台”，核心工作对象不再只有二维图和三维模型，还包括设计 Brief、文化依据、设计转译、材质、结构、功能、版本、评审意见、语音记录、生成配方和提案页面。

产品承诺：设计师可以在一个项目上下文中完成“表达、理解、发散、修改、验证、评审、沉淀和交付”，并且能够解释每个结果从哪里来、为什么这样改、下一步如何继续。

产品不承诺：Rodin 概念模型不是生产 CAD；文化资料未经核验时不能自动成为历史事实；二维和三维生成结果仍需要设计师和工程人员判断。

## 2. 产品定位与目标用户

### 2.1 一句话定位

苏作创意台是一个语音优先、文化依据可追溯、支持二维到贴图三维验证的苏州文创设计工作台。

### 2.2 用户角色

| 角色 | 主要任务 | 需要看到的内容 |
| --- | --- | --- |
| 文创设计师 | 表达创意、修改方案、管理作品 | 全部设计过程、资产和版本 |
| 设计负责人 | 比较方向、评审和定稿 | 已选版本、变化说明、风险 |
| 文化顾问/工艺师 | 核验文化和工艺表达 | 来源、转译、待核验项 |
| 客户/品牌方 | 看方案、评论和提案 | 已确认作品和设计叙事 |
| 项目协作者 | 补充素材、尺寸、场景和交付信息 | 被分配的任务和相关资产 |

### 2.3 首批 Demo 产品

首批 Demo 不使用人物 Q 版案例作为主线，采用三种不同的文创设计问题：

1. **苏州园林 · 漏景香插**：验证文化空间关系、产品结构、材质和功能。
2. **苏州丝绸 · 桌面收纳盒**：验证纹样、材质、色彩和二维到三维表面一致性。
3. **昆曲水袖 · 桌面灯**：验证抽象文化意象、曲面形态、光影和半透明材质。

三个 Demo 覆盖“文化空间转译、文化材质转译、文化意象转译”三类核心任务。

## 3. 用户问题与产品机会

### 3.1 当前痛点

- 灵感在语音或聊天工具里，图片在生图工具里，3D 在另一个平台里，设计上下文不断丢失。
- 一张二维图看起来成立，但无法判断体块、稳定性、使用方式和三维材质是否成立。
- “轻一点”“高级一点”“不要太传统”等意见没有结构化表达，修改常常连带破坏已经确认的内容。
- 苏州文化容易被简化为窗格、拱门和纹样等表面符号，缺少事实、转译和创作之间的边界。
- V1、V2、V3 分散在文件夹中，设计师不知道每一版改了什么、为什么改、哪些内容要继续保留。
- 客户提案需要重新整理文化出处、效果图、模型截图和版本变化。

### 3.2 产品机会

通用生图工具只负责产生图像，通用项目管理工具只负责管理任务。苏作创意台要管理的是中间的设计推理链：

```text
文化事实/素材 → 设计转译 → Brief → 视觉方案 → 三维验证 → 设计决策 → 提案交付
```

## 4. 产品原则

1. **语音主入口，视觉做确认**：用户主要说话，系统必须把理解、变化、保留和状态展示出来。
2. **先复述，再执行**：会改变产品方向的意图必须先得到确认。
3. **文化先解释，再生成**：文化资料先经过来源和转译整理，再进入生成任务。
4. **版本不可覆盖**：每个生成结果都是新版本，原版本可回看、比较、恢复和归档。
5. **方案与版本分离**：方案表示不同创意方向，版本表示同一方向的演变。
6. **二维与三维同源**：Rodin 默认使用已锁定二维候选作为参考，并在三维结果上显示来源。
7. **事实与假设分层**：文化事实、设计转译、设计师判断、AI 推断和待核验内容必须分开标记。
8. **只在关键节点打断用户**：普通讨论不强制确认；生成、锁定、进入三维、交付前需要确认。

## 6. 项目模型

### 6.1 项目不是单条版本线

一个项目可以包含多个设计方向，每个方向有独立版本树：

```text
项目：苏州园林香插
├── 方向 A：漏景
│   ├── A-V1 二维概念
│   ├── A-V2 结构修改
│   ├── A-V3 候选二维
│   └── A-V3-3D Rodin 模型
├── 方向 B：框景
│   ├── B-V1 二维概念
│   └── B-V1-3D Rodin 模型
└── 方向 C：留白
```

## 8. 文化资料和转译系统

每一条文化资料必须区分事实和设计创作：

```text
名称：漏景
类型：文化事实
来源：苏州园林空间语言资料
事实说明：通过遮挡、开口和前后关系形成观看层次
设计转译：前后体块、局部开口、香烟穿行路径
当前应用：漏景香插 A-V1 至 A-V3
核验状态：待补充权威出处
```

标签类型：

- `fact`：文化事实
- `translation`：设计转译
- `designer_decision`：设计师判断
- `ai_assumption`：AI 推断
- `to_verify`：待人工核验

文化资料页必须支持：搜索、收藏、关联项目、查看使用版本、补充来源和标记不适用。

## 10. 语音与对话交互

### 10.1 对话意图

```text
DISCUSS   讨论，不生成
GENERATE  生成二维或三维
MODIFY    修改当前或指定版本
CONFIRM   确认 Brief、候选或阶段
REVIEW    提交评审意见
EXPORT    生成提案或下载包
```

### 10.2 设计补丁

每次修改都转成三个部分：

```json
{
  "base_version": "A-V2",
  "changes": {
    "hollow_structure": "simplified",
    "base_weight": "increased"
  },
  "preserve": ["leak_view", "blue_gray_ceramic"],
  "constraints": ["must_remain_stable"]
}
```

### 10.3 对话确认卡

当用户说“镂空简单一点，底座稳一点”时，界面先显示：

```text
本轮理解
变化：简化镂空、增强底座稳定性
保留：漏景效果、青灰陶瓷、现代风格
下一步：生成二维修改版

[修改理解] [确认并生成] [暂不生成]
```

生成完成后，用户说“这版可以，生成三维”，系统显示：

```text
将使用 A-V3 作为唯一二维参考
输入模式：Image to 3D
模型用途：概念展示
生产可行性：待工程验证

[生成 Rodin 三维] [继续修改二维]
```

### 11.7 页面布局尺寸

桌面端以 1440×900 为设计基准：

```text
顶部全局导航：56px
项目阶段栏：48px
左侧对话栏：320px，可收起到 64px
右侧信息栏：320px，可收起到 64px
中间画布：占用剩余宽度，最小 560px
底部版本胶片条：104px，可收起
```

中间画布优先保留空间。当窗口宽度不足时，先把右侧栏变成抽屉，再收起左侧对话历史，只保留输入区。任何宽度下都不能让主操作按钮覆盖作品。

### 11.8 视觉层级

界面使用低干扰的中性底色，让生成作品成为视觉中心：

- 主画布：浅灰或深灰可切换，作品周围保留足够空白。
- 选中版本：使用单一强调色描边，并同时显示“当前版本”文字。
- 已确认：绿色图标加文字；处理中：蓝色进度加文字；阻塞/失败：红色图标加原因；待核验：黄色标签加文字。
- 状态不能只靠颜色表达。
- 文化事实、设计转译、设计师判断、AI 推断和待核验使用稳定一致的标签样式。

### 11.9 工作台默认视图

首次打开项目时，系统恢复上次离开的方向、版本和画布模式。没有历史状态时按以下规则：

1. 有待确认任务：打开对应任务和版本。
2. 有已选候选：打开候选及其最新关联三维。
3. 只有草稿：打开最近更新的草稿。
4. 空项目：显示语音输入和三个 Demo 启发卡，但不要求用户先选模板。

### 11.10 画布模式切换

画布顶部提供四种模式：

```text
[二维] [三维] [对比] [关系]
```

- 二维：查看当前图、局部区域和生成信息。
- 三维：查看 GLB、材质、视角和二维来源。
- 对比：选择同方向的两个版本，显示左右对比或滑块对比和文字变化。
- 关系：显示文化资料、Brief、版本、二维、三维和提案之间的来源图。

如果当前版本没有对应三维，三维标签仍然可见，但显示“需要先锁定二维候选”，并提供返回二维的操作。

### 11.11 作品库视图

作品库提供两种视图：

- **方案视图**：按项目 → 方向 → 版本分组，适合继续设计。
- **资产视图**：按二维、三维、材质、文化、参考素材、提案分组，适合检索和复用。

卡片点击打开详情；卡片上的快捷操作只保留“设为候选、加入提案、下载、更多”。重命名、复制方向、归档和查看来源放入“更多”，减少卡片拥挤。

批量选择支持：加入提案、添加标签、下载清单和归档。不同项目的资产不能批量设为同一候选。

### 11.12 关键抽屉和浮层

为了避免频繁跳页，工作台使用以下临时界面：

- **生成确认卡**：显示变化、保留、约束和下一步。
- **版本详情抽屉**：显示父版本、来源、Prompt 摘要、任务和评审。
- **资产选择器**：从当前项目或资产库选择参考图、材质和文化资料。
- **任务中心**：显示排队、处理中、失败和已完成任务，关闭后任务继续运行。
- **下载面板**：选择二维原图、GLB、截图、提案和资产清单。

确认卡不使用多层弹窗；用户关闭确认卡后，内容保留为对话草稿。

### 11.13 首次使用导览

首次进入工作台只解释五个区域：说想法、看 AI 理解、看作品、确认版本、进入三维。导览允许跳过，并可从顶部“产品导览”重新打开。

导览使用当前 Demo 数据展示，不创建真实生成任务。完成导览后光标回到语音/文字输入框。

## 12. 二维与三维交互

### 12.1 二维阶段

操作：继续修改、局部圈选、全局重做、版本对比、锁定候选。

局部修改必须显示：修改区域、保护区域、修改描述和生成来源。

### 12.2 三维阶段

三维预览必须显示：

```text
二维来源：A-V3
输入模式：Image to 3D
参考图片数量：1–5
材质状态：已贴图/待确认
概念模型：是
生产 CAD：否
```

三维操作：旋转、缩放、正视图、侧视图、线框、材质查看、二维对照、下载 GLB。

### 12.3 一致性状态

P0 显示可审计来源和待人工检查状态；后续增加轮廓、关键结构、比例和材质四项评分。

如果三维结果基于旧版本，必须标记为 `stale`，不能显示为当前最终模型。

## 13. 生成任务与异常状态

所有任务都要显示明确状态：

```text
排队中 → 处理中 → 已完成
              ↘ 失败 → 可重试
```

图片任务提示：

```text
正在读取 Brief
正在生成二维概念
正在保存新版本
```

Rodin 任务提示：

```text
已读取二维参考图
已提交 Image to 3D
正在生成网格
正在生成材质
正在下载 GLB
已关联到 A-V3
```

失败时保留任务、错误原因和可执行操作：重试、换参考图、回到二维、保存为失败记录。

### 13.1 全局 UI 状态

| 状态 | 中间画布 | 左侧对话 | 主操作 |
| --- | --- | --- | --- |
| 空项目 | 启发卡和开始说明 | 输入框可用 | “记录想法” |
| 正在理解 | 保留当前作品 | 显示实时转写/解释进度 | 可取消本轮 |
| 等待确认 | 显示当前基础版本 | 显示变化/保留卡 | “确认并生成” |
| 二维生成中 | 旧版本保持可查看，新卡片显示进度 | 允许继续讨论 | 不允许重复提交同类任务 |
| 二维完成 | 自动选中新版本但不自动锁定 | 显示结果摘要 | “继续修改 / 锁定候选” |
| 三维生成中 | 可继续查看二维，三维标签显示进度 | 允许继续讨论 | 不允许修改已提交任务的参考快照 |
| 三维完成 | 自动切到三维一次，之后记住用户模式 | 显示来源和限制 | “评审 / 下载” |
| 失败 | 保留最后成功作品 | 显示原因和恢复建议 | “重试 / 换参考 / 返回” |
| 过期结果 | 结果可查看并标记旧版本 | 说明产生时的版本 | “复制为新方向 / 归档” |

### 13.2 保存反馈

所有对话、Brief 和版本变化先在本地状态更新，再显示保存状态：

```text
正在保存… → 已保存
           ↘ 保存失败 · 重试
```

生成任务的提交成功不等于生成完成。界面必须分别显示“已提交”和“已完成”。

### 13.3 空状态文案

- 没有作品：`先说出你的产品想法，系统会整理设计理解并生成第一张概念图。`
- 没有三维：`锁定一张二维候选后，可以从该图生成贴图三维模型。`
- 没有文化资料：`可以先记录设计方向；对外提案前需要补充并核验文化来源。`

- 搜索无结果：显示清除筛选和返回项目全部资产，不自动改变查询。

## 16. 权限与可见性

### 16.1 P0 身份模型

P0 是**单用户、本机运行的可演示产品**，不实现登录、租户、成员邀请和公开分享链接。当前操作者视为项目所有者，可以创建、修改、锁定、下载和归档。评审角色通过“内部评审模式”模拟，用于验证工作流和界面，不保存真实账号权限。

P0 的“客户预览”是本机只读页面或提案预览，不可通过公网分享。页面只显示已选作品、文化说明和提案内容，隐藏 Prompt、失败任务和内部对话。

### 16.2 P1 身份模型

- 增加账号、工作空间、项目成员和异步评论。
- 文化顾问可以核验来源和添加说明。
- 负责人可以通过或退回阶段。
- 内部失败稿和敏感素材可以设置为仅项目成员可见。
- 客户预览链接、访问口令和有效期在 P1 实现。

### 16.3 P2 协作边界

多人同时编辑、实时光标、冲突合并和在线状态属于 P2。P1 只支持异步上传、评论和评审，不做实时协同画布。

## 17. 验收标准

### 主链路

- 用户不填写长表单，只通过一句自然语言创建项目。
- 系统生成 Brief，并明确区分确认值、假设值和待确认值。
- 用户可以通过语音生成二维概念。
- 用户可以用一句修改意见创建新版本，旧版本仍可查看。
- 用户锁定二维候选后才能进入默认 Image to 3D。
- 三维模型保存参考二维 artifact、版本和输入模式。
- 三维结果可以在作品库和作品详情页找到。
- 用户可以从三维模型反查二维来源和文化转译。
- 项目可以生成包含版本号和来源的提案包。

### 资产管理

- 至少支持二维、三维、参考素材、文化资料、材质、结构、对话和提案八类资产。
- 每个资产都有项目、版本、来源和状态。
- 资产可搜索、筛选、查看关系、加入提案和下载。
- 方案分支和版本历史不会混为一条线。

### 失败恢复

- 图片或 Rodin 失败时项目上下文不丢失。
- 失败任务显示原因、重试入口和可替代路径。
- 旧版本和失败版本不会被新结果覆盖。

## 19. 设计决策与待实现边界

本版本明确采用以下设计决策：

- 首个产品 Demo 使用漏景香插、丝绸收纳盒和水袖桌面灯。
- 语音是主入口，但文字输入必须可用。
- 生成结果以不可变版本保存。
- 方案分支和版本树分开。
- Rodin 默认走 Image to 3D，只有用户显式选择时才允许 Text to 3D。
- 三维模型标记为概念模型，不宣称可生产。
- 文化事实、设计转译和 AI 假设分开显示。
- 第一版不做 CAD、供应链、成本和生产排程。
- 2.0 在现有 React/Vite + FastAPI 项目中增量实现，保留当前图片、Rodin、DesignVersion、GenerationJob 和 Artifact 契约；数据迁移通过兼容字段和适配层完成，不另起一套平行系统。
- P0 是本机单用户 Demo，不实现登录、多租户和多人实时协作。
- P0 文本理解使用当前 OpenAI-compatible 文本接口，图片生成/编辑使用当前 OpenAI-compatible 图片接口，三维使用现有 Hyper3D/Rodin CLI 适配器。
- P0 暂不接入真正语音识别服务；界面提供语音入口状态和文字兜底，STT 服务接入放入 P1。已有浏览器语音能力只能作为实验性能力，不能成为验收依赖。
- P0 Rodin 接受一张锁定的主二维图；数据模型从第一天支持同版本 1–5 张参考图，P1 再提供多视图上传和排序 UI。
- P0 Rodin 成果必须是带 PBR 材质/贴图的 GLB，并使用浏览器 Three.js 预览；白模只能作为任务中间状态，不能作为最终作品。
- P0 评审是单人内部评审状态和意见记录；账号化审批、文化顾问流程和客户外链在 P1。
- P0 局部修改入口可以展示，但不进入验收；真正遮罩、保护区域和 inpainting 在 P1 实现。P0 的修改是基于当前二维图的整图编辑。
- P0 仅支持桌面端 Chrome，设计基准视口为 1440×900，最低有效视口为 1280×720；低于该尺寸显示“建议扩大窗口”，不提供完整移动端创作界面。键盘可达、可见焦点、色彩对比和非纯色状态提示属于 P0。
- P0 文件保存在项目本地 `outputs/`，图片单文件上限 20 MB，GLB 单文件建议不超过 100 MB；任务串行执行，同一项目同类任务最多一个 processing，其他任务排队。对象存储、配额、自动清理和成本控制在部署阶段设计。

需要后续在实现前确认的事项：

- 是否允许保存原始语音，默认保存多长时间。
- 提案第一版导出 PDF 还是 HTML/Markdown 优先。
- 文化资料是否需要接入外部权威数据库。
- 生产可行性检查由设计师完成，还是后续接入工程协作者。

P1 客户预览默认使用“无需注册的带访问口令链接”，支持设置有效期；完整客户账号体系不作为当前规划前提。

### 19.1 阶段门与必填规则

P0 使用最少阻塞原则。字段可以处于假设状态，但关键动作必须满足以下条件：

| 动作 | 必须满足 | 可以仍为假设/缺失 |
| --- | --- | --- |
| 生成第一版二维 | 产品方向、使用场景或目标中至少两项已知；不存在未解决的明显冲突 | 精确尺寸、工艺、材质 |
| 修改二维 | 指定基础版本；变化和至少一个保留项明确 | 文化来源可待核验 |
| 锁定二维候选 | 图像生成完成；用户明确确认；失败任务不阻塞 | 精确尺寸、生产结构 |
| 生成 Rodin | 二维候选已锁定；至少一张本地有效主图；输入模式和来源已记录 | 多视图、工程尺寸 |
| 通过内部评审 | 二维/三维来源可追溯；本轮变化和限制已记录 | 生产可行性可标记待验证 |
| 导出内部提案 | 至少一个已选二维作品；文化内容带类型和核验状态 | 未核验内容可带醒目标记 |
| 导出客户提案 | 所有对外文化事实已核验；作品状态为 selected/published；失败与内部资产已排除 | 工程可行性可作为限制说明 |

任何硬门未满足时，界面必须说明“缺少什么、为什么影响下一步、在哪里补充”，不能只禁用按钮。

### 19.2 技术运行边界

| 能力 | P0 实现 | 后续扩展 |
| --- | --- | --- |
| 文本理解 | OpenAI-compatible 文本接口 | 多供应商、成本路由 |
| 语音 | 交互状态 + 文字兜底 | STT、音频保存、说话人区分 |
| 二维生成 | OpenAI-compatible 图片生成与整图编辑 | 遮罩、区域保护、多控制图 |

## 21. v2.1 改进结论

### 21.1 从“生成器”改成“设计记忆系统”

原方案已经能串起生成流程，但专业创作者真正需要的不是更多按钮，而是三个稳定的认知对象：

1. **方向（Direction）**：我正在探索哪一种文化转译和产品策略。
2. **版本（Version）**：这一版相对于上一版具体改了什么，哪些内容被保留。
3. **资产（Asset）**：这个结果以后能否复用、交付、追溯和进入提案。

任何页面都不能把这三个对象混在一起。项目首页管理方向，工作台推进版本，作品库和资产库管理可复用结果。

### 21.2 设计师不需要理解模型，但必须理解状态

界面不展示 provider、prompt token、job id 等内部术语作为主文案，而是把它们翻译成设计师能判断的状态：

| 系统状态 | 主文案 | 用户要知道什么 | 可执行动作 |
| --- | --- | --- | --- |
| `queued` | 已排队 | 请求已保存，还未开始消耗生成资源 | 取消、继续讨论 |
| `processing` | 正在生成 | 当前任务正在执行，旧版本仍可用 | 查看任务、继续讨论 |
| `completed` | 已生成 | 新版本已保存，但尚未代表最终选择 | 查看、比较、锁定 |
| `needs_confirmation` | 等待确认 | AI 已理解变化，但不会替用户做设计决策 | 修改理解、确认生成 |
| `blocked` | 需要补充 | 下一步缺少明确输入或审核条件 | 去补充、返回上一步 |
| `stale` | 基于旧版本 | 结果仍可查看，但不能当作当前最终结果 | 复制、归档、重新生成 |
| `failed` | 生成失败 | 失败原因已记录，项目上下文没有丢失 | 重试、换输入、保留记录 |

### 21.3 八项 builder check 决策

本版本对实现计划中容易产生歧义的事项做如下产品决定：

1. **语音验收边界**：P0 的“语音优先”指录音入口、按住说话交互、实时录音状态和文字兜底；语音转写不是 P0 验收依赖。若浏览器提供 SpeechRecognition，则作为增强能力；不可用时必须能直接输入文字完成同一链路。
2. **提案导出格式**：P0 先输出本地 HTML 提案和 `asset-manifest.json`，同时提供浏览器打印为 PDF 的入口；不在 P0 引入服务端 PDF 排版服务。P1 再增加稳定 PDF 导出和品牌模板。
3. **提案资产持久化**：提案选材保存为项目级 `proposal_asset_ids`，属于 workspace 数据，不是组件临时状态；支持多个二维、多个三维和说明类资产，但每个方向最多一个“主二维候选”和一个“当前最终三维”。
4. **候选切换规则**：同一方向只能有一个当前二维候选。切换候选时，旧二维降为 `reviewing`，基于旧二维的三维全部降为 `stale`，旧资产从提案选材中自动剔除。备选作品仍可以保留在作品库，但不能冒充当前最终结果。
5. **文化核验责任**：P0 只有项目所有者可以把 `to_verify` 改为 `verified`；必须填写来源名称、来源地址或文件标识、引用/摘要和核验时间。没有证据字段的文化事实不能进入客户提案。
6. **PBR 验收标准**：最终三维必须是可解析的 GLB，包含有效材质引用和至少一张纹理图，且材质不是纯白默认材质。若 GLB 可打开但材质检查不通过，只能是 `completed` 的中间结果，不能成为 `selected/published/final`。
7. **局部修改 P0 表现**：按钮可以存在，但文案必须明确为“整图修改（P0）”，点击后展示当前图、修改描述和保留项；不得显示“已圈选区域”“保护区域已生效”等会误导用户的状态。真正遮罩 inpainting 属于 P1。
8. **阶段门操作主体**：P0 的当前项目所有者负责候选锁定、评审、文化核验和发布；客户预览只有只读权限。系统必须记录操作者和时间，不能由生成任务自动把结果标记为发布。

## 22. 端到端用户旅程（可交互版）

### 22.1 首次进入项目

```text
项目首页 → 选择项目 → 选择/创建方向 → 工作台空状态 → 说出想法
```

空状态只呈现一个主动作“说出想法”，下方提供“输入文字”作为同等可用的兜底，不显示复杂模板表单。

系统完成一轮理解后，必须以四段式卡片回应：

```text
我理解的目标
已确认的设计事实
仍然是假设或待核验的内容
建议的下一步
```

用户可以选择“只保存理解”或“确认并生成二维”。没有确认时，不得提交收费生成任务。

### 22.2 从二维到三维

```text
讨论 → 生成确认 → 二维 V1 → 修改补丁 → 二维 V2
→ 锁定二维候选 → 三维确认卡 → Rodin Image to 3D
→ 贴图 GLB → 三维评审 → 加入提案
```

三维确认卡必须明确显示：

- 使用哪一张二维图作为唯一主参考；
- 这是 Image to 3D，不是从文字重新猜形态；
- 结果是带贴图的概念模型，不是生产 CAD；
- 如果二维候选再次切换，当前三维将变为旧版本。

### 22.3 评审到提案

```text
作品详情 → 提交内部评审 → 通过/需要修改/保留备选/淘汰
→ 选择提案资产 → 预览提案 → 检查门禁 → 导出 HTML
```

“需要修改”不覆盖当前版本，而是生成一个带评审引用的设计补丁草稿。用户可以说“处理底座偏轻，但保留漏景比例”，系统自动填入 `changes` 和 `preserve`。

## 23. 页面级交互规格

### 23.1 项目首页

目的：让用户知道“有哪些项目、每个项目卡在哪里、下一步是什么”。

项目卡必须包含：

- 项目名称和产品类型；
- 当前方向和最新版本；
- 当前阶段；
- 二维/三维/文化/待处理数量；
- 最近一次动作；
- 一个主动作：继续工作；
- 一个次动作：查看作品。

项目卡不显示完整 Prompt、不显示失败日志、不把“生成中”伪装为完成。

### 23.2 工作台

三栏不是三个独立工具，而是一条同步上下文：

| 区域 | 负责什么 | 不应该做什么 |
| --- | --- | --- |
| 左栏对话 | 接收表达、复述理解、显示设计决策 | 不隐藏关键确认，不只显示聊天气泡 |
| 中央画布 | 查看当前版本、比较和预览模型 | 不在作品上叠加不可读的操作按钮 |
| 右栏状态 | 显示 Brief、文化来源、阶段门和任务 | 不把所有字段强迫用户一次填完 |

右栏默认分为四个可折叠区：`当前方向`、`设计 Brief`、`文化依据`、`下一步`。每个字段都显示状态标签和来源入口。

### 23.3 作品库

作品库采用“方案视图 + 资产视图”双视图：

- 方案视图按项目 → 方向 → 版本分组，解决“我在做哪条设计路线”；
- 资产视图按二维、三维、材质、文化、过程、提案分组，解决“我以前做过什么可以复用”。

筛选器必须支持组合：项目、方向、类型、状态、文化类型、核验状态、材质状态、是否候选、是否已入提案。筛选结果为空时不自动清除用户条件。

卡片的操作优先级固定为：打开、设为候选/查看候选状态、加入提案、下载；归档、复制方向、查看完整关系放入更多菜单。

### 23.4 资产详情抽屉

详情抽屉采用四个标签：

1. **预览**：图片或带材质的 GLB 预览；
2. **设计说明**：变化、保留、约束、Brief 摘要；
3. **来源关系**：父版本、输入图、文化来源、生成任务、下游模型；
4. **交付状态**：候选、评审、提案、下载和归档状态。

任何“加入提案”成功提示都必须来自服务端返回的已保存状态；刷新页面后仍能看到已选状态。

### 23.5 文化资料卡

文化卡不只显示标题，必须同时显示：

```text
类型：文化事实 / 设计转译 / 设计师判断 / AI 推断 / 待核验
核验：已核验 / 待核验
依据：来源名称 + 地址/文件标识 + 摘要
使用：被哪些方向、版本和提案引用
```

AI 推断不能使用“来源”一词，只能显示“推断依据”和“待人工确认”。

## 24. 作品、资产和提案的数据契约

### 24.1 方向与版本

```json
{
  "direction_id": "direction_1",
  "candidate_2d_asset_id": "asset_2d_v3",
  "current_3d_asset_id": "asset_3d_v3",
  "alternative_asset_ids": ["asset_2d_v2"],
  "version_ids": ["version_v1", "version_v2", "version_v3"]
}
```

`candidate_2d_asset_id` 和 `current_3d_asset_id` 是状态指针，不复制资产本体。切换指针时由服务端同步更新旧资产状态、关联三维状态和提案选材。

### 24.2 项目级提案选材

```json
{
  "proposal_asset_ids": [
    "asset_2d_v3",
    "asset_3d_v3",
    "asset_culture_1",
    "asset_material_2"
  ],
  "proposal_revision": 4,
  "proposal_audience": "internal"
}
```

服务端加入提案前必须校验：资产属于当前项目、未归档、未失败、未过期，且二维/三维满足当前方向门禁。提案生成时重新校验一次，不能信任前端历史选择。

### 24.3 资产状态规则

```text
draft → reviewing → selected → published
                    ↘ archived
processing → completed → selected
           ↘ failed
selected/current → stale（候选切换、输入版本失效或依赖变更）
```

`stale` 资产可以查看和下载，但不能成为当前候选、不能进入客户提案、不能被新任务默认引用。

## 25. 生成任务与可解释性要求

每个生成任务都要保存一份不可变的“输入快照”：

- 当前项目和方向；
- 基础版本/候选资产；
- Brief 修订号；
- 文化来源 ID；
- `changes/preserve/constraints`；
- provider、模型名和任务时间；
- 输出资产 ID；
- 失败原因或重试关系。

界面只显示可帮助决策的摘要，不直接暴露密钥或长 Prompt。用户点击“为什么生成这版”时，看到的是：

```text
基于：A-V2
本轮变化：简化镂空、增加底座重量感
明确保留：漏景关系、青灰陶瓷、现代风格
文化依据：漏景（已核验）
```

## 26. 评审、核验与权限规则

### 26.1 P0 操作权限

P0 单用户模式下，当前项目所有者拥有全部写权限，但仍然要区分动作：

- 生成任务只能创建 `processing/completed` 资产；
- 用户确认才可锁定候选；
- 用户评审才可标记 `selected/published`；
- 用户填写证据才可将文化资料改为 `verified`；
- 归档是可恢复的状态变化，不删除本地文件。

### 26.2 客户提案门禁

客户提案必须同时满足：

1. 至少一个当前方向的已选二维资产；
2. 若包含三维，三维必须来自当前候选二维且 PBR 检查通过；
3. 提案中所有文化事实均为 `verified`；
4. 不包含 `failed`、`archived`、`stale`、`processing` 或未核验的对外资产；
5. 提案页面明确标注“概念模型，不等于生产 CAD”。

门禁失败时必须返回结构化结果：`missing`、`reason`、`action`，并在页面上提供跳转入口。

## 27. P0 验收指标

### 27.1 可用性指标

- 新用户不填长表单，10 分钟内完成“口述 → 二维 → 锁定 → 三维预览”；
- 生成确认卡的变化、保留和约束能被用户一眼区分；
- 任何生成失败都能从任务中心找到原因和重试入口；
- 刷新页面后，当前项目、方向、候选和提案选材不丢失（在 P0 内存生命周期范围内，至少在同一运行实例内保持）。

### 27.2 一致性指标

- 三维详情始终能反查唯一二维来源；
- 候选切换后旧三维立即显示 `stale`，不会继续显示为最终模型；
- 资产详情只展示显式 `source_culture_ids`，不能把项目全部文化资料误显示为来源；
- 所有提案资产都能在作品库定位到原始资产和版本。

### 27.3 视觉与响应式指标

- 1440×900 为基准，1280×720 为最低完整桌面视口；
- 小于最低视口时显示窗口提示，不允许主操作覆盖作品；
- 三栏在窄窗口按“右栏抽屉 → 左栏折叠 → 画布优先”顺序降级；
- 状态不得只靠颜色表达，必须同时有文本或图标；
- 对话、画布、状态栏的宽度变化不能导致卡片跳动、按钮换行溢出或模型预览变形。
